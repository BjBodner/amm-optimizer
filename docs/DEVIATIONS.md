# Deviations from the original (`BjBodner/atm@69828c6`)

This page compares the engine (`amm_optimizer.api.minimize`, whose default `ATMConfig()` is the original ATM sampler) with the original. The public `amm_optimizer.minimize` defaults to the AMM preset `c46` instead; pass `config=ATMConfig()` to it to get the original sampler.

With `ATMConfig(strict_budget=False)` the refactor reproduces the original bit for bit on every scenario in `tests/golden` and on a 400-case random sweep against the live reference (`pytest -m slow`). The differences below are the only ones, and none changes a result on an input where the original ran to completion.

| # | Change | Effect on results | Audit ref |
|---|--------|-------------------|-----------|
| 1 | Import has no side effects: no global seed, no `np.seterr`, no prints; `invalid` floating-point warnings are silenced only inside `minimize`. | Results unchanged once a seed is passed explicitly (`seed=` or `rng=`). | A3, B11 |
| 2 | 1-D problems work (the sample count used a hard-coded row index). | The original raised `IndexError`; the new code runs. Golden scenario `sphere_d1_crashes` asserts "no longer crashes". | B5 |
| 3 | If no search ever finishes with a finite cost the result is `x0` instead of `UnboundLocalError`. | Only reachable after a crash in the original. | B17 |
| 4 | Dead computations are not performed: the "adaptive amplitude" update (it wrote an attribute that was never read), the unused random "directional pool" values (the draws are still made so the stream stays aligned), and sections that run after the budget is gone (they evaluated nothing). | None; verified by the differential tests. | B1, B9 |
| 5 | `OptimizeResult.nfev` is the true number of objective calls. | Reporting only. | B4, B4b |
| 6 | Failed objective values (NaN, +-inf) are handled: each failed point gets the worst finite cost of its batch (or the incumbent's cost), so it can never win and never empties the best-eighth selection. Since 0.6.0 a starting point whose objective is not finite is a failed evaluation too (it raised `ValueError` before). | The original crashed (`ValueError: high <= 0`) once any NaN appeared; for finite objectives results are unchanged (parity sweep). Golden scenarios `nan_d3_crashes` and `nan_far_d3_crashes`. | B14, B20 |
| 7 | Conductor edge cases: a NaN or infinite push now keeps the current allocation (the original set 16 per sampler, i.e. 64 samples on a 60-sample conductor, breaking conservation), and every sampler keeps at least `ConductorConfig.min_samples` (default 1) samples, taken from the largest holders. | The default parameters already satisfy the minimum (unit-norm push gives at least 1.14 before rounding), so results are unchanged; custom springs/couplings used to crash with zero or negative sample counts. | B10, B19 |
| 8 | **Strict budget (default).** At most `budget` objective calls, all counted, including the start-of-search call; a restart reuses the known cost of its start point instead of re-evaluating it; when the budget ends mid-batch the best point evaluated so far is kept (the original discarded the batch and returned a stale cost); `budget < 1` raises `ValueError`. `ATMConfig(strict_budget=False)` restores the original accounting exactly (this is what the parity tests use). | The trace is a prefix of the original's (`budget` calls instead of `budget + 2`), and the result is the best point ever evaluated, so it is never worse and for small budgets much better (a budget of 10 used to return `x0`). | B4, B4b, B6, B18 |

## Still reproduced on purpose (to be evaluated as experiments)

B1 (adaptive amplitude is a static random vector), B2/B3 (RMS and gradient surrogate formulas), B7 (64 vs 60 resources), B12/B13 (meta-cost definitions), B15 (restart thresholds), and B21 (second best for non-positive costs), which has an opt-in fix, `ATMConfig(second_best="exclude_winner")`. These change the algorithm for most runs, so they are evaluated as experiments (phase 8) rather than applied silently.

## Opt-in variants (`ATMConfig.variant`)

`ATMConfig.variant` is a frozen `Variant` whose defaults are the original's behaviour; `Variant()` is bit-identical to the original (the golden, parity, draw-ledger and slow sweep tests run on it unchanged, and `tests/test_config_surface.py` pins every default). A non-default variant needs `strict_budget=True`, has no iteration limit on the hyperparameter rounds (so that saving evaluations can never end the rounds before the budget and restart the search at the incumbent, see `plan.iteration_limit`), and is pinned by a self-snapshot of its own cost trace and draw ledger (`tests/golden_variants.json`, `tools/record_variants.py`) instead of by the original. Experiment ids (E1, E2, ...) refer to the experiment log of the development, which is kept in the separate research archive.

| Flag (default first) | What it changes | Experiment |
|---|---|---|
| `reevaluate_incumbent` (`True`, `False`) | `False`: the incumbent that is the first column of every sampler is not evaluated again; its known cost is used and not charged. The trace is exactly the original's with those 4 evaluations per iteration deleted (tested), so the budget buys about 7% more iterations. Assumes a deterministic objective. Needs a pool of at least 8 samples. | E05 |
| `bounds` (`"none"`, `"fold"`), `corner_clip` (`0.0`) | `"fold"` (needs `minimize(..., bounds=(lower, upper))`): samples outside the box are reflected at the walls before they are evaluated, and the repaired point is stored as the incumbent (the original lets it drift out of the box in 54-88% of iterations at D = 20-40, and 77-80% of evaluated points at 100 x D are outside). `corner_clip=p`: a sample with any coordinate outside is, with probability `p`, clipped onto the box as a whole instead of reflected, so that corner optima (bbob f5, solved by clipping in the original) stay reachable (a per-coordinate rule was measured first and does not: the corner needs every coordinate clipped, probability `p**D`; see the experiment log). Infinite coordinates are always clipped, NaN is left to the objective's failure handling. Costs one `rand` draw per leaving sample only when `corner_clip > 0`. The incumbent column is never touched. | E03 |
| `initial_design` (`"legacy"`, `"uniform"`) | `"uniform"` (needs `bounds`): in the first iteration of every search the non-incumbent columns are drawn uniformly from the box. In the original the first pool lies in a ball of radius 0.015-0.04 around the start (the sawtooth begins at its minimum), so at 10 x D the whole budget is spent there. Applies again after a restart. | E01 |
| `pool_rule` (`"fixed"`, `"budget"`), `pool_min` (24); constants since 0.7.0: `pool_max` (64), `pool_divisor` (30) | `"budget"`: the samples per iteration are `clip(budget / pool_divisor, pool_min, pool_max)`, rounded to a multiple of 4, and set for the first iteration (`initial_population`), the conductor total and the iteration count together by `plan.resolve_config` (the original has these as three separate numbers, 64, 60 and 60; changing one alone makes the conductor pull the pool back to 60 after one iteration). The original runs 3 iterations in 100 x D at D = 2 because of the 60-sample pool. `budget` is the number of evaluations `minimize` is given (the remaining budget after a harness restart). | E04 |
| `amplitude_control` (`"legacy"`, `"success_rate_targeted"`); constants since 0.7.0 (`control.SR_*`): `sr_eta` (1.5), `sr_targets` (.05, .10, .20, .30), `sr_widths` (.5, 1, 2, 4), `sr_max_width` (5) | Replaces the open-loop width of the random search (a sawtooth in an iteration counter, scaled by hyperparameters, times a fixed random vector, with success-triggered resets) by a closed loop: every sampler keeps a scalar log-width, starts at `sr_widths`, and after each iteration moves it by `sr_eta * (success rate - target)`, where the success rate is the share of its candidates (the incumbent column included, as a failure) cheaper than the incumbent; the targets differ per sampler to keep a portfolio of widths; the width is capped at `sr_max_width` and floored at 1e-15. `"success_rate"` (removed in 0.7.0) had no targeted step (`sr` in the review); `"success_rate_targeted"` adds one of a log-uniform multiple (0.1 to 10) of the last move for any non-zero move (`sr2`). The sampler hyperparameters, the meta search's effect on the samples and the growth-factor restart become inert. The four flags `targeted_gate`, `targeted_amplitude`, `reset_on_success` must stay default (they configure the sampler this replaces). `sr_*` do nothing with `"legacy"`. | E02 |
| `es_phase` (`"none"`, `"prefix"`), `es_fraction` (.3), `es_max_budget_per_dim` (1e9); a constant since 0.7.0: `es_init_factor` (1) | `"prefix"` (needs `bounds` and a success-rate `amplitude_control`): the first `es_fraction` of the budget goes to a (1+1)-ES with the 1/5 rule (step `exp(.8/D)` on success, `exp(-.2/D)` on failure, initial step 0.2 of the box width, candidates clipped onto the box so that corners are reached exactly; a noise component that would pull a coordinate that sits on a wall inward is mirrored outward with probability .75, because otherwise a step that leaves k pinned coordinates untouched has probability 2^-k and the ES stalls at a corner optimum such as f5 for D >= 8), started from the best of the given point and `max(4, es_init_factor * D)` uniform points; ATM then continues from the ES incumbent with its start widths scaled by the ES step size, and without its own uniform first pool. Only used for budgets up to `es_max_budget_per_dim * D`; above that the search is ATM alone. On the 5-D sphere it reaches 1e-6 in 384 evaluations (ATM composite 1380, plain (1+1)-ES 387). | E21 |
| `covariance` (`"none"`, `"rank_mu"`), `cov_rate` (1), `cov_select` (.25); constants since 0.7.0: `cov_cap` (1e6), `cov_max_dim` (10, `search.COV_MAX_DIM`) | `"rank_mu"` (needs a success-rate `amplitude_control`): the random search is Gaussian with a full covariance (a D x D matrix, the only one in the package), shape normalised to eigenvalues of geometric mean 1 (the sampler widths keep their meaning), learned CMA-style by a rank-mu update from the best `cov_select` share of each iteration's evaluated samples (displacement from the incumbent in units of the sampler's width, log-rank weights), with CMA's rank-mu learning rate times `cov_rate` and an eigenvalue ratio of at most `cov_cap`; Gaussian noise has the standard deviation of the uniform noise it replaces (1 / sqrt(3) per unit width). Only used up to `cov_max_dim` dimensions. Recommended `cov_rate=3`, `cov_select=0.5`. | E15 |

## Removed in 0.7.0

Release 0.7.0 removed the 92 options and 29 option values that 0.6.0 deprecated (no shipped preset used them), among them the `"success_rate"` amplitude control without the targeted step, `targeted_gate`, `targeted_amplitude`, `reset_on_success` and `noise`; `CHANGELOG.md` lists all of them. The options that every configuration left at one value (the `sr_*` widths, `es_init_factor`, `cov_cap`, `cov_max_dim`, `pool_max`, `pool_divisor` and the routing thresholds) are module constants with those values. Every remaining configuration, the research presets included, runs and hashes exactly as in 0.6.0: `config_hash` re-inserts each removed option at its old default (`config.REMOVED_FIELDS`), and a 0.6.0 configuration dictionary still loads when it holds a removed option at that default.

## Removed again (2026-10-17)

Three opt-in variants were deleted because they were never part of a preset and measured neutral or negative: `allocation="credit"` with `credit_rate`/`credit_floor`/`credit_min_samples` (E18, +.005 with a fixed pool, within noise), `early_accept`/`early_min` (E19, +.003 primary, -.013 at 1000 x D) and `es_init_share` (neutral). Their experiment logs stay in the research archive. Every preset trace (`tests/golden/presets.json`) and every remaining variant snapshot is unchanged; the config hash of a preset changes because the hash covers the field list (the Tier 5 candidate was `a2f27a8ba7e2ed96` at `60412cb`).
